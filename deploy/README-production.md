# Production — краткая памятка развёртывания

Заготовки, не привязанные к конкретному серверу. Приложение остаётся за
reverse-proxy; TLS терминируется спереди (Caddy или облачный балансировщик).

## 1. .env для production (отдельно от локального)
- `ENVIRONMENT=production` — скрывает `/api/docs`.
- `CORS_ORIGINS=https://<домен>` — тот же домен, что в TLS.
- `DOMAIN=<домен>` — используется только reverse-proxy (Caddy), в код не зашит.
- Свежие секреты (НЕ локальные demo): `POSTGRES_PASSWORD` (`openssl rand -base64 24`),
  `SECRET_KEY` (`openssl rand -hex 32`), `ADMIN_PASSWORD` (мин. 10 символов).
- `APP_PORT` наружу не публикуется — порт слушает только reverse-proxy.

## 2. TLS через Caddy впереди (см. deploy/Caddyfile.example)
- Домен из `{$DOMAIN}`; сертификат Let's Encrypt Caddy получает и продлевает сам.
- HSTS ставится на Caddy (во внутреннем nginx его нет намеренно).
- Альтернатива: облачный балансировщик провайдера с управляемым сертификатом —
  тогда Caddy не нужен, а HSTS/редирект 80→443 настраиваются на балансировщике.

## 3. Бэкап PostgreSQL (см. scripts/backup_db.sh)
- Ежедневный дамп с ротацией; каталог `backups/` копировать ВНЕ сервера.
- Раз в месяц — тест восстановления на копии базы:
  `gunzip -c backups/effecom_YYYY-MM-DD_HHMM.sql.gz | docker compose exec -T db psql -U effecom effecom_restore_test`

## 4. Сеть и ОС (уровень сервера, не кода)
- Наружу открыты только 443 (и 80 для редиректа) + SSH по ключам.
- Firewall: закрыть всё остальное; БД и backend уже без портов наружу (internal-сеть).

## 5. Осознанно отложено (ручной режим первого запуска)
- Очередь задач (Redis + RQ/Celery) для AI/парсинга — синхронный режим достаточен
  для ручного темпа; добавляется при росте объёма.
- Интеграции публикации (VK/Telegram/сайт/Дзен) — публикация отмечается вручную.
